# Fixed English pipeline evaluation and answer-correctness confidence

This run evaluates the existing English retrieval, feature, generation and gate controller on 300 new development claims and 300 different confirmation claims. The frozen inputs are in `data/external/fever/pipeline_v1`. Selection excludes all prior project FEVER and XFEVER IDs and normalized claim text, including the completed baseline and temperature-calibration cohorts. Selection continues the fixed SHA-256 ID ranking without using labels or annotated evidence. IDs and normalized text are disjoint across development and confirmation. This remains a new claim sample from the same public FEVER development dataset; shared pages, paraphrases and pretrained-model training overlap are not excluded.

The immutable `config/fever_pipeline_reference_v1.json` contains the existing Qwen2.5-1.5B-Instruct, English DeBERTa NLI and MiniLM embedding identities, recorded inference packages and frozen annotation-completeness gate heads. Models and gate weights are not fitted on this FEVER evaluation. The gate threshold remains 0.5. All four prior policies are evaluated: no gate, NLI gate, embedding gate and combined gate. Do not select a winner or tune a gate threshold using confirmation outcomes.

The separately downloaded FEVER Wikipedia archive/index is reused. Retrieval uses the fixed FTS5 title/body weights 3/1, top three pages and up to three selected sentences per page. Raw page IDs, excerpts and sentence indices are saved before Qwen tokenizer clipping. Claims are limited to 64 tokens and passages to 96 tokens, followed by the existing page-family/exact-text collapse. Source identity here means binding to the pinned benchmark snapshot; it is not historical publisher authentication.

Fresh NLI and embedding features are computed on the actual clipped/collapsed generation context. Their cache entries bind the shown claim and evidence via a SHA-256 digest. The same frozen aggregate features and gate heads feed the existing pre-generation controller. NLI uses 256 pair tokens; MiniLM uses its fixed 384-token maximum. Model inference uses float32, CPU, seed 369 and four threads. Feature models are released before the lazy Qwen backend is loaded.

Qwen uses the unchanged pinned chat template, constrained greedy decoding of Supported/Refuted/Not Enough Evidence, then the existing short explanation prompt. Input prompts must fit 1,024 tokens without silent truncation; generation has a 128-token maximum. The four policies share exact-prompt generation responses within a stage. Prior project responses are never imported. Gate rejection and empty evidence abstain before requesting generation. The existing numeric input check can also reject a verdict/explanation after generation. It checks literal numeric provenance, not factual truth, units or explanation meaning. Abstention is distinct from a generated NEI verdict.

Each accepted final answer receives an uncalibrated score: the mean retrieved-premise NLI probability assigned to the label actually generated, reordered from C/E/N to Supported/Refuted/NEI. This is not the maximum NLI probability unless the generated label matches that argmax. It is not yet a correctness probability. After all development generation, feature and gate outputs are frozen, development gold determines whether each accepted answer's final label is correct.

Fit a separate correctness model for each of the four policies using only its accepted development answers: sklearn logistic regression on the logit of that score, probabilities clipped to [1e-6, 1-1e-6], C=1, max_iter=1000 and random_state=369. No new feature selection or threshold search occurs. If a policy's accepted development outcomes contain only one correctness class, use the predeclared Beta(1,1) smoothed correctness prevalence. If it accepts zero development answers, confidence is explicitly unavailable. These cases remain visible in outputs; no successful calibration is invented.

Freeze those models and bind them to development predictions/gold before starting confirmation retrieval/features/generation. Apply the fits to accepted confirmation answers and save both raw pipeline records and their correctness confidence before opening confirmation gold. No confirmation labels enter retrieval, generation, model fitting or gate threshold selection. Resume uses the frozen fit rather than refitting it. The completed outputs include all policy records, features, prompts, responses, state/rejection reasons, cache identities and scoring receipts.

Report all-claim accuracy and macro F1 with abstentions counted as errors, accepted coverage and accuracy, and reliability of correctness confidence only among accepted answers. Reliability uses binary correctness Brier/NLL and 15-bin equal-width ECE, not multiclass NLI calibration metrics. Compare raw NLI-label scores and fitted correctness confidence. Report risk/coverage by confidence within accepted answers, along with coverage relative to all claims. No guarantee of improved correctness, reliability or selective ranking is made. Request counts are not measured runtime, energy or compute savings.

This evaluates the current English controller, including context-family collapse and numeric checks. It does not complete historical attribution authentication, factual explanation validation or multilingual retrieval/gate transfer. Neither the earlier NLI temperature scalar nor the annotation-completeness gate probabilities are relabeled as confidence in generated-answer correctness.
