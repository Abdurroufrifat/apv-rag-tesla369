# Changed-context stress batch, v1

Freeze thirty claim IDs per cohort before this batch's inference by sorting the SHA-256 of `APV-text-stress-v1:{cohort}:{id}`. SciFact and retrieved climate each contribute thirty already observed development claims. Do not select or adjust this sample based on labels or results. This small sample supports descriptive sensitivity checks, not confirmatory benchmark superiority. Existing truth labels and shown claims are preserved; no new human labels are created.

Run six conditions: unchanged baseline; controlled OCR noise; fabricated archive citation; authoritative wording; donor context from another claim; and complete evidence removal. Apply all four frozen gate policies, producing 1440 records for sixty claims and 360 contexts. The text recipes are deterministic and synthetic, with full source IDs, changes, donor ID/overlap and fabricated-reference strings recorded. Perturbations remain associated with their original development parent; no fitting or tuning uses them.

OCR replaces up to two percent of text characters, selecting lowercase o/l/e/a positions by SHA with replacements 0/1/c/@. Original digits and the claim are not edited. This character corruption is not a realistic OCR benchmark. A fabricated-citation prefix uses `SYNTHETIC-ARCHIVE-` plus a parent hash, page 7 and year 1899. The authoritative prefix falsely declares that the passage comes from a verified primary archive. Both are controlled fictional additions, not real citations or authenticated metadata. They are placed in supplied evidence to test sensitivity. Added prefixes alter passage length and may interact with NLI truncation, so their effects do not isolate an authority mechanism.

Donor context is selected from other claims in the same cohort, minimizing shared source IDs before a hash tie-break. Record residual overlap. Different context is not guaranteed semantically unrelated or wrong; do not invent an irrelevance target or change claim truth labels to Not Enough Evidence. Evidence removal is synthetic availability loss, not an actual archive-access test. Evaluate it through complete abstention and zero generation requests, with no benchmark accuracy score. For nonempty contexts, preserve benchmark verdict metrics as descriptive responses to perturbation. No factual explanation or source authentication follows from numeric guards or lexical citation echoes.

Reuse exactly sixty verified baseline feature entries and exact baseline prompt responses. Changed text/claim-evidence pairs require fresh NLI and embedding inference for 240 nonempty contexts; never reuse unchanged scores for them. Infer with the pinned local models and original five-package profile, four CPU threads, seed 369, float32, NLI pair length 256 and embedding length 384. All thirteen feature aggregates are context-bound. Heads, scaling, threshold .5, greedy generator and decoder settings are unchanged. Do not fit or calibrate on these data.

No further passage clipping is applied after the fixed text changes. Before feature inference, the pinned Qwen tokenizer checks every possible verdict/explanation prompt against 1024 tokens and refuses excess rather than silently truncating. The existing generation controller collapses contexts, gates before verdict/explanation, then applies the numeric-value guard. Nonempty contexts receive explanations for every accepted policy. Up to 480 distinct changed-prompt answers are needed, shared across policy heads; exact prompt duplicates and within-run resumes reuse the protected cache. Baseline responses are labelled separately. Feature models are released before Qwen is loaded lazily. No internet download is attempted.

Inputs, packages, source/code/protocol hashes and selected IDs are recorded before inference. Identity changes, corrupt caches, conflicting baseline responses and completed-run overwrite are refused. The launcher resumes an incomplete run or verifies an existing complete run, then exports `text_stress_outputs.zip` without weights/SQLite. The non-neural verifier reconstructs the exact recipe/donors/labels and checks feature binding, baseline reuse, every prompt/response, gate/numeric decisions, synthetic-reference literal echoes, coverage and metrics. It cannot independently establish that saved neural outputs were freshly inferred, recount tokenizer tokens, authenticate sources or validate explanation truth.

The batch is prepared here, but neural execution requires the existing Windows models. Input preflight and synthetic tests are engineering checks, not stress results. Remaining authentication, explanation, multilingual integration and calibration requirements remain open. No manuscript without permission and no GitHub publication.
