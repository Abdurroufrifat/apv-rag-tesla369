# Learned gate copy/order policy replay, v1

This is a post-hoc engineering analysis of 600 already observed English claims. It connects three frozen matched-rationale heads to the previously verified copy/order generation export. No model training, feature inference, new generation, calibration or annotation occurs. Earlier experiments are preserved.

The baseline consists of 300 SciFact and 300 retrieved-climate contexts from the verified fresh integration export. Its exact per-document NLI probabilities and embedding cosines are reused. Four existing context variants are evaluated: baseline; three copies of the first document with family-linked synthetic IDs; the same copies collapsed before feature calculation and generation; and reversed source order. `copies_raw` is an ablation that explicitly disables normalization. Default collapsed handling is retained in the collapse control. These are controlled copies of whatever was retrieved, not necessarily misinformation and not authenticated independent sources.

For an exact text copy with the same shown claim, copy its recorded C/E/N scores and cosine from its original source. For reversal, reorder those recorded scores with their sources. Recompute all thirteen aggregate features and their context digest for each variant, then apply the unchanged serialized NLI, embedding and combined heads, with threshold .5. The no-gate policy is a control. Refuse changed text, unknown parents, corrupt base aggregates or inconsistent context/source identity. This transformation assumes the fixed per-document scores; it does not test new neural batch/order behavior or feature extraction on changed text.

A rejected gate makes no request for saved verdict or explanation. An accepted gate requests the exact previously generated response for that complete prompt. Missing prompts stop the replay; there is no live fallback. Those answers were generated earlier in an ungated experiment, so this counterfactual policy flow is not a new live experiment and does not demonstrate compute savings. Preserve generator and feature-model declarations, provider packages, source/code/protocol hashes, and record current NumPy/scikit-learn analysis versions separately.

All 600 claims have verdict responses across four conditions. Explanation responses exist only for a fixed label-independent SHA-selected subset of sixty claims per cohort, inherited unchanged from the generation robustness protocol. Therefore all-claim metrics evaluate `gate_verdict_label`, which applies the gate alone. Explanation/numeric metrics evaluate `explanation_guarded_label` only within those fixed subsets, including early abstentions. Never score missing explanations outside the subset as numeric failures or report subset metrics as full-system quality.

The replay exports 9600 policy records (600 claims times four conditions times four policies), 2400 context-bound transformed feature records, all distinct requested prior responses, metrics and an identity receipt. Report completeness probability shifts, threshold acceptance changes, verdict/abstention changes, coverage, all-claim accuracy/F1, covered accuracy, numeric subset rejection and request counts. Completeness probability is the constructed-rationale head output, not probability that a verdict is correct. No Brier/ECE calibration or significance/superiority claim follows from these descriptive comparisons. The existing shared-source dependence and adaptive development limits remain.

Collapsed controls reconstruct the baseline exactly before scoring or prompting; equality is enforced by identical inputs and reused responses. Reverse-order aggregate features preserve the multiset up to arithmetic rounding, while generated answers can change with presentation order. Raw-copy weighting and answer presentation can both affect policy results, so their combined accuracy changes do not isolate the benefit of family collapse.

The verifier independently recomputes the entire replay from the frozen providers and checks every record, feature aggregate/digest, prompt-response binding, subset, numeric guard, identity and metric. It permits declared analysis package differences while requiring identical provider/code/settings/protocol identity and numerically matching replay. It does not read weights or SQLite, rerun tokenizer/neural computations, authenticate sources or establish explanation truth.
